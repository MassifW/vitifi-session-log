# 2026-09-29 17:18 — The backup watchdog, set up and heard from

Continues the 10:03 entry. Mike set up the watchdog from his phone, one
step at a time, while away from the laptop.

## Done

- **A free healthchecks.io check**, "VITIFI nightly backup": expected every
  **1 day**, with **12 hours'** grace before it emails (GitHub has started
  the scheduled backup over six hours late, so less grace would mean false
  alarms). Its address went straight into a GitHub Actions secret, which
  the nightly job reports to after every night — good, or failed.
- The walkthrough's button labels were taken from Healthchecks' own open
  source templates rather than from memory, and matched the screens.
- The backup docs now say what the watchdog's email means and what to do
  about it, and how to replace the check's address if ever needed.
- Keeping the laptop awake for remote use: the app already keeps the
  computer awake while it is working, but not while it waits for the
  next message, so a timed macOS hold was started instead. No setting was
  changed.

## Verified

A backup run by hand after the secret was added: all three checks
passed, the readable copy was kept, and the log says "Watchdog told: a
good night."

## Found

- The laptop slept anyway — its lid was closed, and nothing keeps a
  closed laptop awake. That is why watching the run from the laptop lost
  its connection; the run itself finished normally on GitHub.
- The check's address was visible in a screenshot shared in the chat.
  It can only report to that one check, so it was judged low-risk and
  left as is; it is not repeated anywhere.

## Where I was wrong

I offered to switch on the app's keep-awake setting as if that would keep
the laptop reachable. It was already on, and covers only the time the app
is working. Caught before acting.
