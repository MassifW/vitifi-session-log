# 22 Oct 2026: four features added to the compliance module; release prepared

- **Forms with no signal.** A new record is held on the phone when saving finds no signal and sent by whoever made it when signal returns, on the same shared offline queue as the field screens. Each held signature keeps the phone's own time beside the server's, but only if it is believable (not in the future, not over a month old), so the phone's clock is never the record's. The screen opens from a copy of what the phone last saw, said to be old; with no copy it shows nothing rather than an empty list that would read as "nothing is due".
- **Photos and certificates inside a form.** Kept as entries in the existing Documents store when the record is saved, not when a file is chosen, so an abandoned form leaves nothing behind. Not offered on the private forms: Documents are visible to everyone who can read records, so a photo of an injury would have been wider than the form it came from. A test now enforces that. The suite also caught one of my new question ids clashing with an existing one.
- **An audit view.** For each scheme, every form and policy it relies on with whether the records show it done, what is missing listed first. It says what the app holds and never that a scheme is compliant; with no records it claims nothing is met, and that is tested over the real catalogue.
- **Calendar reminders** from due dates, certificate lapses and policy reviews. Writing the test for it showed that a helper built for a 60-day "needs attention" list was the wrong window for a calendar that can be browsed to next season.
- **A build crash that was not a code fault.** Running a production build while the development server was using the same build folder crashed with an unhelpful error. The same commit built cleanly in a separate copy, so the cause was the clash, and builds are now run in isolated copies.
- The release was prepared (all tests, typecheck and an isolated build pass; no database change pending) but the final step, moving the live branch, was blocked by a permission rule and left for a person.
