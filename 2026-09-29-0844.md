# 2026-09-29 08:44 — Start a ferment, the manual, and reference documents a machine keeps honest

*Block layouts, vine counts, yields, input products and rates, client
names and certification details are withheld from this public copy.
Here that means record counts that describe the vineyards, and the lot
and site names. The private copy has them.*

Mike asked for the project's reference documents to be kept up to date —
a file directory, every outside service the app needs (with
alternatives), and everything about uploaded documents and downloadable
data, because "all the data input" must be readable outside the app if it
goes down or someone stops using it. Also: a list of unreleased,
uncommitted, unresolved and suggested items; "Start a ferment"; and, mid-way,
"a user manual should be part of the program". Applied to the live
database on his word; not yet released.

## Found

- Of the logs he named, only the services list existed in the project,
  and it was out of date. The file directory and the data document were
  created fresh.
- **Nothing in the app could start a new vintage's ferment**, so a new
  season's fruit had nowhere to go. And the harvest screen offered every
  lot of the vintage — press blends and topping wine would have appeared
  as fermenters once the first tank was pressed.
- **A night's backup can be skipped silently.** GitHub had not started the
  scheduled run five hours after its time; a run started by hand passed.
  A failed run raises an alarm; a run that never starts does not.
- **The Spray Diary's "Recommendations" tab runs on placeholder inputs**,
  so its advice comes from nothing. The manual now says not to act on it.
- **Only two things can be downloaded**: every uploaded file as a zip, and
  the spray diary as a spreadsheet file. Everything else is only in the
  database and its nightly backup — restorable, but not readable by a
  person.
- Some of last vintage's source spreadsheets live only on one laptop, and
  the map's pin images load from other people's servers.

## Built

- **Start a ferment**: its name, tank, variety and day, on the Ferments
  screen. One database function makes the ferment and records the tank,
  as the signed-in person, all or nothing; a name already used in the
  vintage is refused whatever its capitals; a tank the records think is
  busy is marked, not refused. The ferment appears on the list straight
  away, knows its tank for the first reading, and is offered on the harvest
  screen until it is pressed.
- **The user manual, inside the app**: a section for each tab plus getting
  started, working without signal, fixing mistakes, and getting your data
  out; it opens at the tab you came from, and a search finds any answer.
  Its test fails if a tab has no section, or if the manual names a button
  the app no longer has — so it cannot quietly drift from the screens.
- **Reference documents**: the services list rewritten with every outside
  service, what it does, and what could replace it; a document of every
  kind of record and how to get it out without the app; a file directory;
  and an open-items list (unreleased, uncommitted, unresolved, suggested).
  A test fails when a folder, document, source file, download or outside
  address exists that the documents don't mention, and a small command
  prints what is waiting for a release straight from git.
- Mike's list of features to add is recorded: a photo pinned with its
  place, time, comment and row (for the tractor seat), external laboratory
  analysis, topping, bottling, a chemicals register, maintenance and
  training records, and a calendar.

## Verified

On a fresh restore of the live database: the new function's self-check
(10 checks, rolled back); the rewritten ferment status compared row by
row with the old one — identical; the whole flow in a browser; the full
suite. Then on live: applied; both entry self-checks pass there and leave
nothing behind; the full suite passes against live.

## Where I was wrong

The self-check first used a vintage the function itself refuses; the file
directory's first draft missed two source files and misplaced one; a SQL
check had an operator-precedence slip; the first version of the new test
was too strict about how folders are named.

## Not done

A readable export of every record — the top suggestion; hiding the
placeholder recommendations; a watchdog for missed backups; correcting a
pressing; the feature list. The release waits for Mike.
