# 22 Oct 2026: a QR page for visitors and contractors, an owners' notice, and a log

- A visitor or a contractor can now scan a code at the gate, read the site rules (and, for a contractor, an induction), sign with a finger, and sign themselves out from the same page, with no login. The owners see arrivals in a notice at the top of the app and in a log. A contractor signs in on the page each visit; the longer yearly agreement stays a form done with staff.
- This is the one place a person with no login writes to the database, so it is built narrowly: four small database functions the public key may call and nothing else (still no table), each checking its own input in full and returning only what its caller needs, a limit per hour and per day, and a trap field for bots. What the page may show is a switch on each library document, off by default. The form's copy is built in SQL from fixed text, never from the caller, and a test compares it with the code's. The sign-out token is long and random, only its hash is kept, in a table nobody can read.
- Reading the existing record trigger before changing it turned up a real weakness: its guard on who may edit a completed record compared an empty author to the caller with an equals sign, which gives null rather than false, so the check was silently skipped for any record without an author. Fixed, with a test that proves it.
- Tried first on a restored copy of the database, not the live one: the new checks and the whole test suite pass there, and the real flow was exercised in a browser from a visitor's side and an owner's. Several of my own mistakes in the new test harness were caught that way.
- Whether yearly re-signing is required for contractors: nothing in the project's notes requires it; the certifying standard asks for a review at least every three years and the Act sets no period, so the yearly agreement is the winery's own practice and the app follows it and says so.
- Not done: the migration is not on the live database (waiting for a yes); nothing released.
