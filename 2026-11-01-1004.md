# 1 Nov 2026 — Icons on the Map: placing inside a block, a Standard style, and icons a winery makes

**Asked (Mike):** three things about the new icons on the Map.
1. A tap inside a block selected the block instead of placing the new icon there.
2. The pixel icons are fun but hard to tell apart, so there should be a choice of standard or pixel icons.
3. Could a user make their own icons for the menu?

**Why 1 happened:** each block outline on the map is an interactive Leaflet polygon with its own click (select the block, open its card). Leaflet gives a tap on such a layer to the layer and not to the map, so the placing step never heard it.

**Done** (on a branch, PR #47; no database change):
- **Placing anywhere.** While the map waits for the tap, a class on the map makes every drawn shape (block outlines, vine dots, other icons) let the tap through to the map itself, and any open card is closed. The icon goes where the tap lands, inside a block or not.
- **Pixel or Standard,** chosen per phone, pixel the default. Standard keeps each icon's plate (ISO 7010's green and red squares, yellow triangle and blue circle for the safety signs, a white tile for the rest) with a plain line drawing on it. Most drawings are from Lucide, the icon set the app's buttons already use (ISC licence, its notice kept with them). The pump, valve, tap, farm gate, spill kit and drop-off, and the sign shapes for first aid, "i" and "!", were drawn for the app. The map, the key, the menu and the printed safety map follow the choice; the print draws the same paths on its canvas, so map and paper match.

**Found while checking, and fixed:**
- The printed safety map drew each block's name at the block's middle whatever was there. No icon could be placed there before today, so it never showed. Now an icon there moves the name just above or below it.
- The standard water tank looked like the common "database" symbol; it now carries a drop.

**Checked:**
- On a local copy of the night's backup, in a browser as a test owner, at desktop and phone width: a tap inside a block placed the icon there with no block selected.
- With the fix switched off by hand, the same tap selected the block and opened its card, exactly the reported fault. So the change is what fixed it.
- An icon saved inside a block. Standard remembered after a reload. All 27 icons looked at in both styles. A print made in Standard.
- No console errors.
- The full test suite passes (the database suites were not run in this folder; the change touches no database); typecheck and build pass. The local copy was torn down after.

**Corrected:** a date in the open-items list said the safety points were seeded on live at a UTC time after this session began; the backup taken the evening before already held them, so the date was a day early.

**Question 3, answered, not built:** yes, possible. Any form of it needs a table of each winery's own icons (behind the same per-winery wall and safety rule), the menu check widened, and a database migration with Mike's yes.

Three forms:
- pick a symbol from a wider library and name it;
- a 16 x 16 pixel editor in the app, stored as text like the built-in icons;
- upload a picture (the most flexible, but hardest to read at icon size, and limited to PNG or JPEG because an SVG can carry script).

Recommended: pick a symbol and name it, with the pixel editor as an optional second step. Waiting for Mike's choice.
