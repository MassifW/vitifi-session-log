**Built** (branch `claude/table-statistics-check`):
- `supabase/migrations/20261124100000_table_statistics_check.sql`: `verify_table_statistics()`. For every table of ours in
  `public` (extension tables such as `spatial_ref_sys` left out), it asks whether the table holds a row and whether
  `pg_stats` has anything for it. It fails on any table with rows and no statistics, naming them and the `analyze`
  that would fix them. It also fails on a table it cannot look into, and on seeing fewer than 50 tables or fewer than
  20 with statistics, so a check looking in the wrong place does not read as a clean database. It reads only; it
  runs as the caller; only the service key may call it; 60 s limit.
- `tests/table-statistics.test.mjs`: what the SQL must say (reads only, never runs analyze itself, failures named,
  the security), and a live suite that calls it.
- `tests/security-surface.test.mjs`: the new function on the harness list.
