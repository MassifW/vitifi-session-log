# 30 Oct 2026 — The schema test reads an rpc call's top-level arguments only

**Found (by the sensor-research session):** with `.env.local`, `npm test` failed `tests/schema-contract.test.mjs`: `skipPlannedSprays` was said to pass `outcome`, `date` and `notes` to `record_spray_report`, which takes one `p jsonb`. A false alarm: the call passed `{ p: { plan_event_id, outcome, date, notes } }`. The test's pattern for an rpc call's arguments stopped at the first `}`, so the inner object's keys were read as arguments. The skip-planned-sprays change had been gated in a cloud session, where the live suites do not run, so it reached `main` unseen. The call was already rewritten to `const p = {...}; rpc(..., { p })` this morning (68f0446), which hid the bug but left the parser able to raise the same false alarm again.

**Changed in the test:** `topLevelKeys` reads the arguments object by depth, stepping over strings, template literals and comments, so a brace, comma or colon in one of them is not structure. A shorthand `{ p }` now counts as passing `p`: the twelve such calls were checked for no arguments at all before, and all twelve pass. A spread or computed name at the top level is reported as unreadable instead of passing nothing (none in the app today). The argument check is now one function, used by the real test and by a new live test that feeds it the nested call: right as written, wrong when `p` is renamed `p_report`. A test that runs without the live database checks the parser on the nested call, shorthand, arrays, calls inside values, and a string, a template and a comment holding braces.

**Checked:** across all 91 rpc calls in `app/`, the new parser reads the same names as the old one except the twelve shorthand calls. With the app's call put back temporarily to its original nested form, the test passed; with `record_blend`'s `{ p }` renamed to `{ p_blend: p }`, it failed with exactly that one message. Both app files restored before the gates.

**Then, with Mike's yes ("Yes, add it"):** a call whose arguments are passed in a variable is now reported as unreadable, so it fails the run instead of passing unchecked. There was one: the racking screen's topping-wine credit, `.rpc('record_left_behind', credit)`, whose eight names the test could not read. It now names them in the call: the same object, nothing changes on screen. With the old call put back temporarily, the test failed naming `rackingActions.ts:417`; with the new one, all eight names are accepted by the function on live. This is the only app code in the branch, so a release would carry one rewritten line and nothing else.
