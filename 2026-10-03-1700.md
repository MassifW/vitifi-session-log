## What was built (no database change)

- **"Add and copy a link"** is now the main button on "Add a colleague".
  It makes the login with the admin API's `generateLink` (type invite),
  which sends nothing, then adds the staff row as before, as the owner.
  "Email an invitation instead" stays for when there is a sender.
- **"Copy invite link"** sits beside anyone active who has not chosen a
  password. It makes an invite link for an address never opened, and a
  recovery link for one opened without a password chosen: the same two
  cases as "Resend invite".
- **The link** is the app's own address with `token_hash` and its type
  (`inviteLinkFor`, `app/lib/authLink.ts`), the form the app has read
  since 27 Sep.
  - It opens the app directly rather than Supabase, so the redirect
    allow-list plays no part.
  - It is redeemed only when the page calls `verifyOtp`, so a messaging
    app's link preview does not use it up.
- **On screen**, the link is copied for the owner automatically (with a
  fallback when the browser refuses), shown in a box to select, and comes
  with the instruction to send it to that person only. It works once and
  expires; a new link retires the old.
- **The guard against an existing login** (one made more than a minute
  before its invitation is refused) applies to the link path unchanged.
- **Uses of the service-role key**: 3 calls in `authActions.ts`, up from 2.
  `tests/security-surface.test.mjs` is updated with the reason.
