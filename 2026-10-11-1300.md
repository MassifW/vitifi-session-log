# 11 October 2026 -- moving wine between lots in a vessel

Mike's brief: keep six outstanding workstreams in memory and start with the flagged discrepancies in a client's
Chardonnay (one lot booked more wine than fruit, another far less; a vessel was probably topped with the second).

## Finding
- The reconciliation screens only read: nothing could move litres between lots, so a mis-booked or topped vessel
  could be seen but not repaired. Every error needs to be repairable in the app.

## Built
- A database function that books litres in a vessel to another lot as a correction: each movement that filled the
  vessel is superseded by a smaller one, the other lot gets a new one, one record says who and why; nothing edited or
  deleted; undone by moving the same litres back. Refuses, in words, another owner's wine, another vintage, more
  litres than the vessel holds, and wine that arrived from another vessel.
- A "Move wine between lots" button on a flag in Cellar -> Check, offering only lots of the same vintage, owner and
  variety. Tried on a restored copy of live through the real screen; the Check went clean and the original entry stayed
  on record.

## Mistakes
- The first version refused the real data because imported movements carry a source line, which my made-up test rows
  lacked. Lesson: try a new function on a restored copy of live, not only on invented rows.
- A test date before the function's 2000 cutoff failed the first self-check run.

## Open
