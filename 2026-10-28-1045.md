# 28 October 2026 — photo tags offered again once added; the location question

Mike, from a phone screenshot of the photo card: "every time I add a photo, the app asks for me to confirm location access but without offering a permanent 'allow'" and "I've been trying to 'add tag' in the app but this doesn't save. If i add a new tag, this new tag should then appear in the menu above the 'another word' box."

- **Tags: they did save, but were never offered again.** A word typed into "Another word" and added with "Add tag" was attached to that photo and saved with it; the photo card then offered only the eleven starter words, so on the next photo the word was gone and it looked unsaved. The Photos tab's tag filter already listed it. Now `listFieldPhotoTags()` (`fieldPhotoActions.ts`) reads every tag on a current photo (corrections in, removed photos out), the card offers them beside the starter words, and so does the Photos tab's "Correct". The phone keeps a copy (`fieldPhotoTagsCopy`), shown at once and with no signal, and a photo's words go into that copy as it is saved or held, so they are offered on the very next photo even before the server is asked. No database change.
- **Location: the iPhone's question, not the app's.** A web app cannot give itself permanent location access; Safari asks a website each time unless the phone's own setting says otherwise. The fix is on the phone: Settings, Apps, Safari, Location, "Allow"; and Settings, Privacy & Security, Location Services, Safari Websites, "While Using the App" with Precise Location on. The manual's Photos page now says so, with a line on adding tags. The app's own asking is unchanged: it still asks only for a photo taken just now that does not say where it was taken. Not tried on Mike's phone; the exact iOS menu names depend on the iOS version (iOS 18 moved Safari under "Apps").
- **Checked:** typecheck, build, and 1,982 tests pass (the manual's label test first failed on "Precise Location", an iPhone label, now listed as the phone's own); the 70 live-database suites did not run here (no `.env.local`). Not tried in a browser: this worktree has no `.env.local`, so no signed-in screen could be loaded.
- **Mike tried it: Settings, Apps, Safari, Location, "Allow" stopped the question on its own.** The second step (Location Services, Safari Websites) was not in his list, so the manual now gives only the step that worked.
