## Documents

Built on the owner's "go ahead". The database part is on live; the
screen waits for the next release.

- A document is a file with:
  - a title, a kind (lab report, certificate, safety data sheet,
    specification, form, other) and its date;
  - when it lapses, if it does;
  - notes;
  - what it is about: wine lots, barrels, blocks, vineyards or products,
    or nothing for the winery as a whole.
- **Append-only, like every record.** A correction is a new version, and
  keeps the file and attachments unless it gives new ones; a removal
  says so. The file is never overwritten or deleted: the private bucket
  has no update or delete policy.
- Files are named by the app so the storage reads without the app:
  `<kind>/<year>/<date>-<title>.<ext>`.
- A Documents tab with search and a kind filter. Files open through a
  short-lived private link, in a tab opened during the tap so phones
  don't block it as a pop-up. A wine lot's and a barrel's own screens
  list their documents, and the section is absent when there are none.
  Lapse dates show within two months.
- Included in the spreadsheet export, the file download and the nightly
  copy.
- **Tested:**
  - 23 rolled-back database checks run as four kinds of user, locally
    and on live;
  - a full add, open, correct and remove in a browser, against a local
    restore of last night's backup.
- Two design gaps found and fixed before anything went live:
  - a correction silently dropped attachments;
  - the planned "valid until" date and product links were missing.
- Not tried by hand: the two late additions, because the hidden browser
  panel never starts a freshly loaded page. That was checked, not
  assumed: the page reports itself hidden and gets no animation frames.
- The project's schema check caught a column list it couldn't read; it
  is now checked against live like every other.
