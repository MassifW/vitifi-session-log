## What was installed

eslint 10.11.0, eslint-plugin-react-hooks 7.1.1,
@typescript-eslint/parser 8.70.0. No ESLint existed in this project at
all before today. Flat config in `eslint.config.mjs`.

**Two rules, not the preset.** v7 also ships the React Compiler's lint
suite — purity, immutability, refs, set-state-in-effect and a dozen
more — under `recommended`. That is a separate decision with a
separate noise budget, and enabling it tonight would have been exactly
the "other building" that is on hold. The two rules here are the ones
that describe how React actually behaves at runtime.

  rules-of-hooks    error     a component that calls hooks in a
                              different order on different renders is
                              broken, not untidy
  exhaustive-deps   warning   sometimes deliberate, and only the
                              person who wrote it knows which

No `project` setting on the parser: both rules are syntactic, and
asking for type information would make the lint as slow as a build for
no extra finding.

## The lint is a test, not a step before one

`eslint && node --test` means a lint error hides 220 test results and
a test failure hides the lint. `tests/eslint-hooks.test.mjs` runs
ESLint's own Node API inside the suite, so it cannot be skipped and
both signals are always reported. `npm run lint` still exists for
humans and for `--fix`.

This is the same principle as the reconciliation panel: a run that
reports one thing while silently not having checked the other is the
failure mode, not the convenience.

## What the plugin found

**Zero rules-of-hooks errors.** Both bugs from this afternoon were
already fixed, so there was nothing left to catch. 115 files linted,
39 of them .tsx.

Four warnings, reported and **not fixed**, per instruction:

**1. `app/components/Map/AddLayerFlow.tsx:299` — useCallback missing
`reset`.** Worth more than its severity. `reset` is a plain function
redefined every render, and it closes over `previewUrl` to revoke the
object URL. The submit callback captures whichever `reset` existed
when its own deps last changed. Those deps include `name`, and `name`
is set in the same handler and the same render as `previewUrl` — so
today the captured `reset` always holds the current URL and the bug
does not fire. It is safe by coincidence of ordering, not by
construction. If that ordering ever changes, `reset()` revokes a stale
URL and leaves a live one un-revoked, which here means an orthomosaic
blob of a couple of hundred megabytes held in memory. Fix is to wrap
`reset` in `useCallback`.

**2. `app/components/MapLocationPicker.tsx:171` — the Leaflet init
effect, `[]`, commented "Only run once on mount".** The empty array is
right: re-running it tears down and rebuilds the map. But the click
handler registered inside closes over the **first** `onLocationSelect`
forever. If the parent ever re-creates that callback over changing
state, clicks call the stale one. The dependency array is not the bug;
the captured callback is.

**3. Three `eslint-disable-next-line react-hooks/exhaustive-deps`
directives that predate any linter**, written against a rule that had
never run. Removing each and re-linting showed which were real:

  VineyardMap.tsx:207    LOAD-BEARING — hides a genuine missing
                         dependency on `initMap`
  VineyardMap.tsx:329    does nothing
  SprayDiary.tsx:139     does nothing

The load-bearing one sits on the effect that contains
`setNeedsPlaceSearch(true); return;` — the same early return that bug
2 this afternoon fell below.

## The regex test, measured

`tests/fixtures/hook-violations.tsx` holds six deliberately broken
components and three correct ones. Every offending line is tagged
`// VIOLATION:`; the test reads those tags and checks both directions,
so a missed violation and a false positive fail the same way.

Against that fixture:

  shape                                      regex test   plugin
  hooks inside a useEffect body (shipped)        miss       catch
  hooks below a nested early return (shipped)    catch      catch
  hook inside a plain if                         miss       catch
  hook in a loop                                 miss       catch
  hook in a non-component function               miss       catch
  hook after a single-line early return          miss       catch
  return inside a callback (correct)             pass       pass
  custom hook with a conditional return value    pass       pass
  setters inside an effect (correct)             pass       pass

**One of six.** And the one it missed most sharply is the one it was
written for: its second test, "no hook is called inside another hook's
callback", excluded `useState` and `useRef` from the search to avoid
flagging the setters that legitimately appear inside an effect body —
and that exclusion swallowed the real violation, which was a
`useState` inside an effect body. **It would have missed the bug a
second time.**

That is now twice the same test was wrong about the same bug: its
first version missed it through the indent regex, its second through
the exclusion list. Retired.

The one thing worth keeping from it is its third test — the guard that
the scan had actually looked at something. ESLint passes just as
silently if a `files` glob stops matching or an `ignores` entry grows
too broad, so that assertion survives as "39 .tsx files were linted".

## Every assertion proved to fail

Not assumed — each break was made, run, and reverted:

  a conditional hook added to LayerPanel      -> test 1 fails
  exhaustive-deps promoted to error           -> test 3 fails
  one fixture VIOLATION tag removed           -> tests 4 and 5 fail

And one that failed for the wrong reason first: the fixture originally
carried a blanket `/* eslint-disable */` at the top so `npm run lint`
would skip it. That disabled the rule for the *test's* run too, and
the fixture reported zero violations and looked like a pass. The
config's `ignores` does the job instead, and the test lints it with
`ignore: false`. That near-miss is recorded in the fixture's own
comments, because it is the same failure the whole exercise is about.
