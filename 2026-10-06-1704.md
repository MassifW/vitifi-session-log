# 2026-10-06 — External laboratories: sample codes, lab adapters, a confirm step

Mike: "We'd like to have some integration with external labs (analysis
requests and perhaps automated report recieval and integration where
possible) ... Focussing on fermlabs but with a view to maximally
facilitating ease of sample submission and report receival with any lab
(Hill labs would be another example)".

A design session; nothing built. Written up as `docs/lab-analysis.md`.

## What was looked at

- **FermLabs' intake** (`fermlabs.web.app/intake`), opened in the
  browser pane and its public JavaScript read. It is the lab's own
  Firebase LIMS (clients, samples, work orders, an approval queue; the
  "Report Issue" link goes to their GitHub organisation). Pre-registration
  posts JSON to `/api/submitIntakeRequest` **with a reCAPTCHA token**;
  returning clients give client number + postcode. **No URL pre-fill**:
  the form reads nothing from the address. Nothing was submitted.
- **Their test menu is public data**: `/api/listPublicTestMethods` and
  `/api/listPublicTestPanels` return stable IDs, codes, units, sample
  types and numeric/string result type (read with GET, as the page does).
- **The ten FermLabs reports** in `data/documents/2024/Lab external/`
  (#24132 to #26019): text PDFs; one line per sample and test with the
  lab's sample number, the winery's sample ID, analyte, result, unit,
  analysis date, method. A throwaway parse (scratchpad, not kept) read 125
  results; it missed qualitative ones ("Brettanomyces Not detected") and
  lines where the sample ID ran into the analyte name. So the layout moves
  a little; a reader is feasible but needs a person to confirm.
- The winery's sample IDs on those reports are shorthand (`CAABEL FR`,
  `BBHCEx2`, `TOPBLEND`) against app lot names like `CA abel`: the case
  for VITIFI issuing the sample code.
- Reports are addressed to several company names and two client numbers
  over 2024–26. Not interpreted; asked.
- **Hill Laboratories**: a REST API with JWT (create order, results push
  notification, report download, job history), onboarding 2–6 weeks by
  arrangement (cx@hill-labs.co.nz); cannot place an order charged to
  another organisation. mylab portal; PDF request forms incl. grapevine
  tissue and soil/plant. The API's result fields were not seen in detail
  (the public docs describe operations only; summarised through WebFetch,
  so lower confidence on specifics).
- In VITIFI: lab results fit the existing `observation` event (method +
  provenance, decisions.md "Observations"); Documents already has "lab
  report"; **wine analyses (pH, malic, SO2, VA) are not recorded per lot or
  barrel anywhere in the app yet.**

## The proposal

VITIFI owns the sample (a code tied to what it came from, on the bottle
and the form), so results match themselves. Each lab an adapter at three
levels for requests (API / copy-ready web form / filled PDF + CSV) and
three routes for results (API / email-in / drop-in), all through one
confirm screen beside the PDF before results become observations;
"could not read" is said, never dropped. FermLabs: ask for a pre-filled
link or a client key (their reCAPTCHA is not to be worked around). AI
PDF reading is a services decision. Order: hand entry of analyses first,
then codes/labels/requests, FermLabs reader, email-in; talk to both labs
early. Five questions for Mike (open-items).
