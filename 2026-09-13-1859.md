# Status audit — 13 September 2026

Went through the project's own decision log in full and swept the codebase directly for everything flagged, deferred, not built, or left as a known limitation — cross-checked the highest-stakes claims against the live database rather than trusting the doc. Also closed six previously-open questions in the same session.

## Headline findings

- The Spray Diary's "Recommendations" tab runs entirely on hardcoded/fake data end to end: a literal placeholder growth stage passed in from the main page, a hardcoded product list standing in for the real product database, and a spray-history input that's permanently empty. Only the weather feeding it is real. Not something the decision log said this bluntly — the code sweep found it.
- No authentication and no row-level-security policies exist anywhere in the schema — every table has RLS enabled but zero actual policies, and the app runs entirely on a service-role key with no per-user identity. This is the one hard blocker on deploying anywhere reachable from the internet.
- A full cellar/winemaking data model (vessels, movements, lot parentage, blend composition) is designed in the database and was verified once against synthetic test data, but zero code anywhere in the app actually queries any of it — the single biggest "built ahead of the feature" gap in the app.
- A planned certification/compliance permissibility check (so a spray could be flagged against whichever schemes the operation holds before it's applied) is documented as an intention but has no table and no code behind it yet.
- Two things the decision log claimed were true turned out to be stale once checked directly: a "no vine position data exists" note is now wrong (position data was loaded in a later session, though nothing queries it yet), and a "LINZ map layer still a placeholder" note turned out to already be resolved.

## What's blocked on what

- **Code only, nothing external stopping it**: the fake recommendations pipeline, auth/RLS, the cellar model's UI and server actions, the certification check, a few data backfills, and a refactor to thread the new growth-stage descriptor lookup through a handful of string-building functions that still print a bare stage number.
- **External**: Harvest still haven't replied about an API key for their weather stations; a published veraison/lag-phase baseline covering more of the season doesn't exist yet; Clos Miki needs more field phenology readings before its own growth-stage estimates can reach the same confidence Pisa's do; one product needs an ACVM registration lookup before its PHI status is settled; a licensed grapevine growth-stage chart (or someone drawing one) to replace the copyrighted one this app can't ship.
- **A decision from Michael**: whether to reconcile block F's as-planted boundary against its original 2020 design (a real, measured discrepancy, not acted on yet), and whether to re-target 15 already-imported Pisa spray events to a finer block-level split than the source diary itself used.

## Closed today

- Block D's and block C's historically-separate sub-areas (more wind-exposed and rockier than the rest of each block) were confirmed to be a historic distinction, not a current management need — recorded so the boundary is explained rather than rediscovered as a mystery.
- Clos Miki's Pergola zone confirmed not-yet-productive directly, not inferred from consistency with neighbouring zones the way it was before.
- Fermenter tank capacities for both sites, found on their yield sheets and recorded — not imported into the vessels schema, since nothing in the app queries that table yet.
- Landpro confirmed no surveys exist beyond block F — that item is closed, not pending; nothing more is coming.
- Four products with previously-unconfirmed application units were confirmed as powders and corrected in the database.
- One vine clone's name ("10/5" — a real New Zealand selection) was confirmed correctly stored as text everywhere in the app, and confirmed to be the *only* place in either site's yield workbook where Excel's own auto-formatting had corrupted a clone name into a date on a previous open. No export in this app currently emits clone data, so nothing was actually broken; the CSV-safety mechanism that would protect it if one's ever built (built in an earlier session) was confirmed to already handle this exact case correctly.
- Harvest still haven't replied — left open, unchanged.

One new item surfaced: ten Clos Miki vine-position records ("gap cells") still need a physical field walk to resolve — separate from a larger set of positions already confirmed permanently unresolvable without a different source document.
