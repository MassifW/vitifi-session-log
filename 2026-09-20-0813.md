# One ledger, measured volumes, and drawn-shape resolution

*Volumes, yields, vine counts, block layouts and input rates are withheld
from this public copy.*

## 1. One ledger

**No data migration was needed.** Every row of the old flat ledger was
already present in the new header/line one — the earlier backfill had
converted them, positive rows becoming movement headers and negative rows
becoming movement lines. Verified one-for-one on event, vessel and
volume, with nothing unmatched.

**Equivalence was proved before and after repointing the reads**: every
destination blend by barrel count and litres, the full lot list, every
row of the lot balance view and every row of the vintage balance view —
all identical. Every cellar read now goes through one conversion instead
of five separate queries against the old table.

**Retired by rename, not drop.** The old table is the imported record of
the source barrel logs, and the project's own decisions say imported
source data is not altered. Renaming retires it in the sense that
matters: anything still reading the old name now fails at the first query
rather than quietly returning a second, diverging view of the cellar. A
test asserts that read fails.

The generator scripts still write inserts against the old name. They are
historical, and re-running one would now fail — which is correct, since
the ledger they target no longer exists.

## 2. Measured beats rated

Seven movements had a header volume disagreeing with their own source
lines, and in all seven the header was exactly the vessel's rated
capacity — the barrel log's volume column records what the barrel holds,
not what went into it.

**Three were corrected**, where the press sheet's measured volume fits
inside the vessel. The measurement wins; the rated figure is superseded,
not deleted; and the corrections are explicitly marked as measurements
rather than assumptions.

**Four were not**, and this is why it was done case by case rather than
by rule: in each of those the "measurement" is *larger* than the vessel
it supposedly went into. Those figures are what left the fermenters, not
what arrived — the difference is lees, or a second destination the record
does not name. Preferring them would assert a physical impossibility.
They stay flagged in the reconciliation panel, which is where a
discrepancy nobody can resolve from the record belongs.

**Effect**: the vintage's recovery drops by about 1.7% relative. That is
the size of error that had been sitting in the headline figure.

## 3. The mislabelled block: blast radius

Introduced when the plantings were imported, fixed about a day later.

**Stored: nothing** beyond the planting row's own block reference. The
harvest pick tables are empty, and the composition table links to the
planting rather than the block.

**Views: none affected** — the one that exposes a block has no rows.

**Composition: unaffected.** The provenance layer groups plantings by
block, but no harvest pick resolves to either of the two blocks involved.
The function never looked either of them up.

**Figures quoted: none wrong.** The vine reconciliation that was reported
sums all plantings regardless of block, so it was right throughout and
passed as a test while the bug was live.

**Unlike the earlier missing-block bug, this one reached nothing.** That
one put a wrong split on screen for a dozen lots. This one's only visible
consequence was the new harvest screen's planting dropdown showing the
wrong block letter for one entry, live for a few hours, during which
nothing was entered.

Worth noting the area-selection layer was never wrong — it had both
blocks correctly all along. Only the plantings layer was affected.

## 4. Drawn shapes

**Every vine now carries a position.** They never had one; the column has
existed since the core schema and was empty.

The first attempt placed each vine at a fraction of its row's surveyed
line length, assuming those lines span the rows end to end. They do not —
one block's surveyed line is a small fraction of the fruit its rows
carry — so every vine past the line's end clamped to the far end and each
row collapsed to a single point.

Rewritten to take the row's **start and bearing** from the survey, which
it is good for, and its **length from its own vine count times the
block's vine spacing**, which is recorded data. Measured spacing now
matches the stated spacing exactly for every block, including both blocks
named in the acceptance criteria. (One of the two stated figures differs
in the second decimal from what is on record; the recorded value was
used.)

Row spacing measures wider than stated wherever rows converge, because it
is taken between same-index vines in adjacent rows and that is a
diagonal. Geometry, not error, and noted on the view rather than silently
corrected.

A shape drawn on the map now resolves to the vines inside it, grouped by
the planting each sits in, with that planting's clone and rootstock
apportioned over them — **the same basis as a row range, and exact on
exactly the same condition**: that only one clone is in scope. A shape
over a single-clone block comes back exact; one over a mixed planting
comes back as an estimate and says so. Resolution takes under 200 ms.

A shape reports **every block it crosses**, not just the one it was aimed
at, which is what lets a picker see the blob is not what they meant
before anything is saved. Both the shape and the resolved vine set are
stored: the shape is what was meant and is the only thing that can be
re-resolved later; the vine set is what the model computes with.

## Not done

- **The drawing UI.** The resolution, the preview and the storage are
  built and tested; putting a polygon tool on the map is not. There is no
  draw library in the project, and the existing drawing component renders
  computed polygons rather than accepting drawn ones.
- **One block has no planting record.** A shape over it resolves its
  vines correctly but reports no clone or rootstock, because that section
  of the source sheet was never parsed into the plantings table. That is
  the gap to close before a pick there can report composition at all.
