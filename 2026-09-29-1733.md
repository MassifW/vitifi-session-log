# 2026-09-29 17:33 — The 2024 workbooks are kept in the repository

*Nothing in this entry falls under the six things the public copy
withholds.*

Until today, the winery's 2024 vintage workbooks existed only in a folder
on one laptop. Mike asked for them to be copied into the project.

## Done

- **Seven workbooks copied** into the project's source-data folder under
  their own names, byte for byte (each copy's checksum matches its
  original): the barrel log, the weigh sheets and daily ferment log, a
  barrel map, pre-harvest samples, the pre-vintage volume plan, a blending
  tasting, and the bottling and dry goods workbook. The originals are
  untouched.
- **Not copied**: laboratory report PDFs, suppliers' quality certificates
  and a supplier form — not workbooks, and not what was asked for. The
  lab reports were offered separately, since they belong with the
  lab-analysis feature on the wanted list.
- The 2024 import script now reads the project copy by default.
- The 2024 acceptance tests read the project copy too. They used to skip
  themselves whenever the workbooks were absent — which was every
  machine but one. Now a missing workbook fails them (it would mean a
  broken checkout), and only a machine without the Python spreadsheet
  library skips, saying why.
- The file directory lists each workbook with what it fed, or that it was
  never imported.

## Verified

The import script's output from the project copy is byte-identical to
its output from the original folder (with Python's hash seed fixed;
otherwise one mapping's key order varies run to run, with the same
content). The reconciliation tests and the document tests pass with the
files tracked.

## Found

Five of the seven were never imported, and they cover gaps the app still
has: 2024 bottling, barrel positions, pre-harvest sampling.
