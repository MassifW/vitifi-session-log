# 2026-09-29 07:49 — Pressing into barrels, and the name alone

*Block layouts, vine counts, yields, input products and rates, client
names and certification details are withheld from this public copy.
Here that means every litre and kilo figure, the litres-per-kilo factor,
and the lot, blend and barrel names, which can name a client's label.
The private copy has them.*

Mike asked for a way to record pressing and barrelling down for this
season: the ferment view could show last vintage's barrels, but nothing
could enter a new pressing. Partway through he asked for the header to
read just the app's name, since the vineyards using it need not all be
in one region. Applied to the live database on his word; not yet
released.

## What the records said before building

- **A press blend collects over days.** Last vintage's press-blend
  barrels took press wine from up to six ferments each, pressed on
  different days. So the screen records *this* ferment's share into a
  shared barrel, under the blend's own lot; the next ferment adds its
  share the same way.
- **Most barrels are full on paper**, because their racking and bottling
  have not been entered; only a handful read as empty. A picker of empty
  barrels would have offered almost nothing, so every barrel is offered,
  with a line saying what the records still claim.
- **Every fermenter reads empty**: crushing is not recorded as a
  movement, so the ledger never credits a tank.

## What was built

- **One database function saves a whole pressing, all or nothing, as
  whoever is signed in** — so row-level security decides (the cellar
  book), and a phone that loses signal part-way has saved everything or
  nothing. It writes the pressing event, a barrel-down movement per
  barrel (free run, press run or press blend), a line naming the
  ferment and its tank, any new barrels, press-blend lots and their
  parentage — the same shape last vintage's imported records have, so
  every existing view reads it unchanged. Sent twice, it lands once.
- It refuses, in words, what cannot be true: no barrels, a tank pressed
  into itself, a date after tomorrow or before the fruit went in, the
  same barrel twice, a new barrel with no size, a blend with no name, or
  a blend that would make a lot its own ancestor (the parentage walk
  behind every volume would never end). The phone checks the same
  things first, in the same words, so nothing that will be refused is
  queued.
- **On the ferment screen**: "Record the pressing" under the day's
  reading while a ferment is on skins, "Record more barrels" once it is
  pressed (a press run the next day). Tap barrels from a list that finds
  a code typed any way; tap free run, press run or press blend; the
  litres start at each barrel's rated size and are marked rated until a
  measured figure is typed. A blend's name fills itself from the barrel
  it is already in. A line warns — never blocks — when a figure would
  fill a barrel past its size. With no signal the pressing is held on
  the phone and sent later, like a reading.
- **A defect fixed on the way**: after a reading was held on the phone
  with no signal, the ferment screen tried to refresh, failed, and
  replaced itself with "could not load", taking the "kept on this
  phone" line with it. It now keeps what it had, says it is the last
  loaded copy, and loads again when the signal returns.
- The header and sign-in page show just the name.

## Verified

On a restored copy of the live database: the function's self-check (23
checks, as a throwaway cellar hand under row-level security, all rolled
back); the whole flow in a browser at phone width, including a pressing
held with the server stopped and sent exactly once afterwards; the full
suite. Then on live: applied, the self-check passes there and leaves
nothing behind, the full suite passes against live, typecheck and build
clean.

## Where I was wrong

The first self-check run caught the function letting a barrel with no
size reach a database constraint instead of saying so; the first full
test run caught a call shape the schema-contract test could not read;
the first barrel list put fermenters at the top; the first totals line
compared one ferment's fruit with another ferment's share. Two page
reloads during testing are most likely the development server reacting
to my own edits — not proven.

## Not done

  harvest screen offers only existing lots — so this season's ferments,
  and this screen, cannot be reached until that exists. Before harvest.
- No way to correct a pressing from the screen yet (the ledger is
  append-only; a correction is a new, superseding record).
- The release, which Mike will call when a few changes are ready to go
