## Found

- **Supabase refuses any file name with a non-ASCII letter** ("Invalid
  key: étiquette.jpg"). So no such name can reach the copy, and photos
  must be named by the app, not the phone. My own test data had one,
  and that was the 400 the previous session stopped on.
- **The "JWT issued at future" failures are probably not the laptop's
  clock**, which is what I blamed on 29 and 30 Sep. The laptop is about
  5–6 s fast (measured against GitHub's servers). But the failing request
  used the secret key, and for that key Supabase mints the token on its
  own servers, so the laptop's clock never enters into it. The likelier
  cause is a clock difference inside Supabase. That is unproven, and it
  is out of our hands; reruns pass.
- `gh repo create --push` chose an SSH address, and this laptop has no
  SSH key on GitHub. The README went up over HTTPS with `gh`'s own
  login, for that one command only.
