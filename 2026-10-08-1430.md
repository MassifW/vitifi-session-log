# 8 Oct 2026 -- Tastings: score, blend call and comment per barrel

The winemaker, finalising blends, wants the barrel log sheet's tasting record (a score, a blend category and a comment per barrel, with every earlier tasting still visible) in the app, with the ability to hide or show data on request so it is not overwhelming.

## Findings
- The sheets stack each sampling round for a barrel as its own dated row, so the history is all there to import: several hundred dated tastings across two sites. The sheet's right-hand columns are plain sums (latest score, an average over scores above zero, latest category, how often the barrel has been called what it is called now).
- Barrel destinations were already modelled per barrel with history; scores and comments were not recorded anywhere, and nothing in the app could record a call.

## Built
- A tasting is an observation against the barrel and the wine in it (no new event type): score 0 to 5, the blend category as written (kept raw when nobody has named it), comment in the notes. Saved by one database function as the signed-in person, all or none, idempotent, corrections and removals as new records. A call that changes the barrel's current destination also writes the new assignment; one that agrees writes nothing.
- Cellar -> Taste: a sheet that opens with four columns (latest score, average, call, latest comment) and shows more on request from chips the phone remembers; barrels can be grouped by call with litres and average score per group; a barrel opens to its full history, narrowed to scored or commented; a round of tastings is entered with last time's tasting shown beside each barrel.
- The sheets' history is read and held for checking before anything is imported.
- A 29-check live-database test, a new export file (tastings.csv), manual, data and file docs.
